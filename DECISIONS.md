# Обґрунтування технічних рішень (DECISIONS.md)

**Проєкт:** ARGUS Events — Вебінтерфейс журналу подій чергового оператора  
**Слухач:** Кучер Володимир, 231 група  
**Тема:** Розроблення вебінтерфейсу журналу подій чергового оператора системи наземного моніторингу руху морських і повітряних об'єктів

---

## 1. Збереження токенів автентифікації (Token Storage)

### Прийняте рішення:
Токени доступу (`access_token`), ідентифікації (`id_token`) та оновлення (`refresh_token`) зберігаються у **`sessionStorage`** веббраузера за допомогою `WebStorageStateStore` з бібліотеки `oidc-client-ts` (конфігурація в `src/auth.js`).

### Обґрунтування:
1. **Ізоляція робочої вкладки:** `sessionStorage` доступний виключно в межах поточної вкладки або вікна. Після закриття вкладки або браузера сесія автоматично знищується, що критично важливо для робочих станцій чергової зміни центру моніторингу на спільних терміналах.
2. **Захист від несанкціонованого доступу:** На відміну від `localStorage`, чутливі JWT-токени не залишаються на постійному диску комп'ютера після завершення сеансу чергового оператора.
3. **Відмова від `localStorage`:** Ми відмовилися від `localStorage`, оскільки безстрокове зберігання токенів у сховищі браузера на спільних консолях створює серйозний ризик компрометації облікових даних.
4. **Порівняння з `HttpOnly Cookies`:** Сервіс SENTINEL функціонує як незалежний OpenID Connect Authority (`/oidc`) для SPA-клієнтів через стандартний протокол OAuth 2.0 Authorization Code Flow + PKCE (`S256`). Без створення додаткового проксі-шару (Backend-For-Frontend, BFF) збереження токенів у `sessionStorage` є рекомендованим стандартом IETF (OAuth 2.0 for Browser-Based Apps).

## 2. Рівні та порядок виходу із системи (Logout)

У підсистемі реалізовано комбінований двоетапний процес виходу:

1. **Локальне очищення (Client Cleanup):**
   - Видалення профілю та токенів із пам'яті клієнта (`userManager.removeUser()`).
   - **Повне скидання Redux-сховища:** виклик `store.dispatch(resetStore())` обнуляє всі накопичені записи подій `records`, статус запитів та оперативні лічильники, щоб наступна зміна не бачила даних попередньої.
   - **Закриття каналу WebSocket:** відписка від подій та закриття сокета для запобігання фоновій передачі даних.

2. **Федеративний вихід (OIDC Logout):**
   - Виклик `userManager.signoutRedirect({ post_logout_redirect_uri: window.location.origin })` для інформування провайдера ідентифікації SENTINEL про завершення сесії SSO (Single Sign-On).

## 3. Обробка помилок `401 Unauthorized` та `403 Forbidden`

1. **Помилка `401 Unauthorized`:**
   - Перехоплюється централізовано у функції `authFetch` модуля `src/api.js`.
   - Застосунок намагається один раз оновити access-токен через `renewToken()` (`userManager.signinSilent()`), використовуючи `refresh_token`.
   - У разі успіху запит автоматично повторюється з оновленим Bearer-токеном.
   - Якщо сесія повністю протермінована, користувач спрямовується на екран входу SENTINEL.

2. **Помилка `403 Forbidden`:**
   - Виникає у разі спроби виконання неавторизованої дії (наприклад, користувач з роллю `analyst` намагається виконати операцію старшого оператора).
   - Застосунок інформує про відсутність прав, не скидаючи поточний стан таблиці подій та не розриваючи сеанс роботи.

3. **Код закриття сокета `1008` (Policy Violation):**
   - Якщо сервер розриває WebSocket через застарілий токен (код 1008), клієнт автоматично поновлює токен і відновлює з'єднання.

## 4. Розмежування ролей (`analyst` та `operator`)

- **`analyst` (Аналітик):** переглядає оперативний потік подій, деталізує інформацію та здійснює індивідуальне квитування (`Acknowledge`).
- **`operator` (Оператор):** володіє розширеними правами — масове квитування всіх відкритих подій («Підтвердити всі»), налаштування та експорт.
- Елементи інтерфейсу, призначені виключно оператору, автоматично приховуються для користувача з роллю аналітика.

---

## 5. Чотири стани компонента `RequireAuth`

Компонент `src/ui/RequireAuth.jsx` забезпечує захист основного вікна та коректну реакцію на всі стани автентифікації:
1. **Перевірка (`isLoading`):** відображення скелетонів та індикатора завантаження без мерехтіння інтерфейсу.
2. **Помилка (`error`):** відображення повідомлення про недоступність служби авторизації з можливістю повторити спробу.
3. **Неавторизований (`!isAuthenticated`):** екран входу з кнопкою авторизації через SENTINEL OIDC.
4. **Авторизований (`isAuthenticated`):** робочий інтерфейс журналу подій.
